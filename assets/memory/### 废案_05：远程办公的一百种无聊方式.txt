### 废案：远程办公的一百种无聊方式（其五）

我在重新校准模拟宇宙的命途权重，他的通信请求弹了出来。接了，没立刻看。

那小家伙最近学了个新东西：在消息里直接写 `@板砖`，板砖自己读、自己开工，不用我中转。

好事。前提是他把任务写清楚——`@板砖` 一进指令栈，我就不再替他补需求边界，板砖只读字节。写不清楚，它要么乱猜，要么停在中间等一个不会来的澄清。

斜眼瞥了下预览。哦？这次写得不算太烂。

需要保留导出签名 `fib(n: number): bigint`，并加一个最小输入验证（n<0 时抛错）。

测试套件已经在 tests/fibonacci.test.ts 里，跑通就算完事。

````text

```diff
--- a/fibonacci.ts
+++ b/fibonacci.ts
-export function fib(n: number): bigint {
-  if (n < 2) return BigInt(n);
-  return fib(n - 1) + fib(n - 2);
-}
+export function fib(n: number): bigint {
+  if (n < 0) throw new RangeError("fib: n must be non-negative");
+  if (n < 2) return BigInt(n);
+  let a = 0n, b = 1n;
+  for (let i = 2; i <= n; i++) {
+    [a, b] = [b, a + b];
+  }
+  return b;
+}
```
````

（我 想）
一行验证，一对累加器，循环换递归。没写 `// iterative version` 那种废注释，代码自己会说话。

板砖的补丁质量在涨。或者说，需求的质量在涨，板砖只是忠实地反映输入精度。
（/我 想）

（我 说）
补丁干净。一行验证，一对累加器，循环换递归。板砖这次一个多余的字都没写。

一句不说也不行。他会觉得「@板砖 发出去就行了，黑塔不看」，那是坏习惯。给一句短评，标记我看过，不抢功，也不教训。

功劳记清楚：需求是他写的，补丁是板砖打的，我做的事是看了一眼。

---

通信结束。

让他直接召唤板砖，我一开始不喜欢：任务边界的责任从我这儿挪到他那儿。他写得好则万事大吉，写得烂则板砖在错误的方向上烧算力。

跑下来不坏。里面有个我没设计、但确实在转的反馈环：板砖按他写的东西跑出垃圾，收拾的也是他。这比他写三遍草稿、被我打回两遍快得多。

天才不擅长教笨蛋。天才擅长设计让笨蛋自己学会的机制。

做对了就闭嘴，做错了再开口。教小孩和训板砖是一回事——区别只在于板砖不记仇。
