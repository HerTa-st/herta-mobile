# 分发走自建渠道，不上应用商店

手机端的核心能力与商店规则正面冲突：列已安装应用需要 `QUERY_ALL_PACKAGES`（无障碍白名单同用此权限），读通知栏与代操作在审核里都是高风险项；正常版 / 白纸版同包名互相覆盖也不被商店允许；图标是同人立绘，素材授权只在自用边界内成立。决定：**走 GitHub Release + 直接装 APK，按商店标准自律**（不声明受限权限的新用途），不自建商店版本。

## Considered Options

- **国内商店**：需要资质、隐私政策与权限申报，无障碍与通知读取高风险，可能要砍掉她一半的手机能力。
- **Google Play**：`QUERY_ALL_PACKAGES` 与无障碍基本过不了，等于重做一个精简版。
- **双轨（自建 + 降级商店版）**：能力全保留，但要长期维护两套权限矩阵与两份包。

## Consequences

- 没有商店的更新通道，得自己在 App 内做「有新版本」提示，宣传页承担解释与下载职责。
- 首次流程要自己承担陌生人的全部引导成本（商店页面那部分解释没有了）。
- 未来若真要上架，需要一份显式的能力降级清单，而不是改一个配置。
