# 主题扩展停在 CSS 层，组件槽位只接受随包代码

主题市场需要「让第三方大改风格」，但主题来自陌生人。决定：分四层扩展点 —— **L0 token**（15 个全局颜色，可校验、可回滚）、**L1 CSS 全接管**（主题自带 CSS，按 `data-part` 语义锚点覆盖任意样式，含 grid/order 重排）、**L2 组件槽位**（消息气泡与消息项 / 左轨+顶栏 / 输入条 / 开屏四块可整块替换，但注册表只接受随包代码）、**L3 第三方代码永不开放**（代码里留空注册表）。

## Considered Options

- **只给 token**：最安全，但换不了风格，达不到「大改」的需求。
- **开放组件注册（第三方 JS）**：扩展性最强，但任何主题都能读她的记忆库、发网络请求。
- **公开类名而不是锚点**：零新增属性，但那些类名从此冻结，内部样式再也不能重构。

## Consequences

- 主题改不了 DOM 结构——这是刻意的上限；要加节点只能改 App。
- 主题 CSS 与用户设置冲突时**用户优先**：`当前的脸` / 聊天背景 / 日间夜间 / 字体，主题盖不掉。
- 每次结构重构只需保住锚点，不必保住 class。
- 前置债：`settings-suite.css` 的 28 个 `--ss-*` 局部 token 必须并回全局，否则最小契约缺四页。
