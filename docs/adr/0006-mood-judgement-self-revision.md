# 心情判定可以由她自己改写，但只动三段文字

心情判定原本是一个打包的静态 JSON：八种状态、逐条触发描述、判定边界、优先级。这等于她每天用哪套语气，是**别人写死的**——和「语气笔记要她自己写」的初衷矛盾。现在允许她自己改，但把可改范围收窄到三段：

**触发描述**（什么算雷区、什么算好感区）、**判定边界**（一句话像多个状态时怎么归）、**优先级**（同时成立时的先后）。

八种状态名、输出格式「状态名|触发」、数值护栏（三小时回落、连两次才认）由代码锁死，不在可改范围。

两条路：对话里她可以调一个写工具当场改（必须带理由与至少一条证据）；深睡成功后再自查一次，只在有信号时动。两条路共用一个版本号与五版快照；改动只在「设置 → 她自己改过的判定」里可见。

## Considered Options

- **整段提示词交给她重写**：自由，但 6KB 里一半是例子和边界，容易把她写成通用客服，也容易丢输出格式。
- **只允许改触发描述**：最保守，但判定边界与优先级恰恰是「判错」最常见的来源。
- **允许增删/改名八种状态**：最彻底，但心情名是素材 `metaThink.preThink` 的键；改名/增删会让这一轮的语气旁注直接落空。
- **连数值阈值也能改**：能治「她一轮一个样」，但那是防止状态抖动的护栏，不该由被护栏保护的一方来调。
- **只写草稿、要用户确认**：最稳，但那就不是「她自己改」。

## Consequences

- 她改坏的第一次会被结构校验挡住（状态名不齐 / 输出格式丢了 / 超字数），拒绝理由回给她，她下次知道为什么没改成。
- 名字不动，所以「改动后的判定」与既有素材、旁注、测试仍然对得上。
- 只能在设置页看到改动，她不会为此发消息、也不占主动机会——代价是你可能很久都不知道她改过。
- 与自动语气共用同一个深睡成功挂载点；省 token 模式、无 key、离线都不跑。
- 判定日志（最近若干次判定）只给她复盘用，不扩成「心情历史」界面——那是另一件事。
