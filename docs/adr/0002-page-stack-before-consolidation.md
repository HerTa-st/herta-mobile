# 页面栈与语义锚点先于入口收拢

手机端 12 个可到达界面现在是一堆布尔量叠在同一个聊天壳上（`App.tsx` 77KB，没有 router、没有返回栈），所以每加一个页面都要自己造返回，「同一件事散在四处」也没有技术手段收拢。决定：**先建页面栈（每个页面有稳定 route 标识、能压栈退栈、能被通知深链直达），并给关键节点加 `data-part` 语义锚点，再做入口收拢与主题系统**。

## Considered Options

- **继续用布尔量，逐个补返回逻辑**：每次加页面要写一遍返回，且主题没法依赖结构，最终会成为第二块巨石。
- **引入 react-router**：能拿到栈，但本机应用没有 URL 语义；真正需要的是「一个显式的 route 标识 + 一个栈」，几十行足够，不需要一个为浏览器设计的依赖。
- **先铺锚点再建栈**：锚点要挂在结构上，结构未定就会白铺。

## Consequences

- 第三批「收拢入口」依赖它：没有栈，收拢只会把散的东西换个地方散。
- 主题 CSS 契约依赖 `data-part`：只承诺锚点、不承诺 class，之后重构样式不会打断所有主题。
- Android 返回键行为在这批统一，不再逐页确认。
