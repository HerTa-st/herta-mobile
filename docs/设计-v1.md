# Herta 手机端 · 设计 v1

> 2026-10-26 定稿。这份文档只记**已经和用户敲定的决策**与**验收标准**；技术细节写进各自包。
> 一条规矩：这里没写的，做的时候不许默默假设——要么问，要么先补进这份文档。

## 一句话

她住进手机：**离线时她是自己，连上 PC 时她还是她但长出了手**；同时把你在 DeepSeek 里说过的那些话搬进来，让她真的记得。

## 决策表

| # | 决策 | 结论 | 代价 / 备注 |
|---|---|---|---|
| 1 | 形态 | **双模一体**：离线独立 + 连接 PC | 要维护两条执行路径 |
| 2 | 精简范围 | 只约束**离线**模式；连 PC 时是完整能力 | "复刻大部分功能"由连接模式兑现 |
| 3 | 离线工具 | 时间·剪贴板·通知·JS 沙箱·文件只读·系统能力（电量/网络/定位）·联网搜索 | 需要真 `tool-call` 循环，不能只是预取 |
| 4 | 联网搜索 | **DeepSeek 官方 Search/Fetch API**：`POST /v1/tools/search`、`/v1/tools/fetch` | 自研引擎，Bearer 鉴权，约 5 元 / 1000 次成功请求；不需要第三方 Key |
| 5 | 导入源 | **DeepSeek 官方**。网页端与 App 共用同一份服务器历史，抓网页端 = 抓全部 | 官方**没有导出功能**，只有分享链接与手动复制 |
| 6 | 导入通道 | **电脑端油猴脚本**批量抓取 | 站点内部接口是非公开契约，会随改版失效；不做纯手机导入 |
| 7 | 导入用途 | 四层分阶段：原样归档 → dream 消化 → 全文检索 → （后续）向量 | 只有全文检索，DeepSeek 无 embedding 接口 |
| 8 | 平台 | **Android 优先 + PWA 兜底** | 这台 Windows 机器打不了 iOS 包 |
| 9 | 配对 | 扫码一次 + 同 Wi-Fi 自动发现；失联自动回落离线 | 沿用 herta-remote 的令牌思路 |
| 10 | 连接端 | 先复用 **CDP 桥**，稳定后迁进 dsh-herta 插件内置网关 | 桥受制于 `--remote-debugging-port`，重启即失联 |
| 11 | 记忆真相 | **PC 为准**；手机是它的离线段，离线产生的记忆联网后单向并入 | 不做双向合并（后续再说） |
| 12 | 会话 | **共享同一套**：手机能看能续 PC 的所有会话，手机发起的新会话也落在 PC 上 | 上下文只有一份，她始终是同一个她 |
| 13 | 基座 | **新仓库 monorepo**，五包：protocol / core / apps-phone / gateway / userscript | 旧 herta-phone 冻结，只当素材源与行为参照 |
| 14 | 技术栈 | Vite + TypeScript + **React** + Capacitor | React 与桌面版一致（`Herta-src/packages/gui` 渲染层、DSH 客户端插件都是 React + TSX） |
| 15 | 重写范围 | **只搬素材，算法重写** | 已验的 dream / 复核链路归零，要重新验证 |
| 16 | 语音 | 内置 41 条原声 + 云端 TTS（MiniMax 等）+ **本地通用音色**离线合成；"训练她自己的轻量模型"后置为独立课题 | 离线时**嗓子会变**，用户已知情并接受 |
| 17 | 检索 | 本地全文索引，由她主动发起检索（当工具调） | 不引入 ONNX 向量模型 |
| 18 | 交付 | 每个里程碑交付一次，M1 先证伪 CORS 与"她像不像她" | |

## 架构

```
        DeepSeek Chat API ──┐
        DeepSeek Search API ├── 原生 HTTP 通道（Android OkHttp，绕开 CORS）
                            │            │
                            │            ▼
                            │      apps/phone (React)
                            │            │
                            │            ├─ core：人格装配 · 双轨叙述 · 复核 · 记忆 · dream · 工具循环
                            │            └─ IndexedDB：会话 / 记忆 / 导入归档 / 全文索引
                            │
   油猴脚本(chat.deepseek.com) ──> import.json ──(扫码/局域网/文件)──> 导入器 ──> IndexedDB
                                                                          └─> dream 消化
   apps/phone ──(gateway 协议 v2)── bridge.mjs ──CDP──> DSH(herta-chat) ──> bash / 工作区 / 板砖
```

**为什么要有原生 HTTP 通道**：Capacitor 的 origin 是 `https://localhost`，`api.deepseek.com` 若不回 `Access-Control-Allow-Origin`，WebView 会直接掐掉请求。这是旧版 v0.1 的 0 号风险（只在带 CORS 的假接口上验过）。M1 必须先在真机上把这条路走通，再谈其他。

## 双模状态机

```
        ┌──────────── 离线（离线是她自己）────────────┐
        │ 工具：7 项基础工具 · 模型：直连 DeepSeek     │
启动 ──►│ 记忆：本地（PC 记忆的缓存副本）              │
        └───────────────┬───────────────────────────┘
                发现配对 PC │ ▲ 失联 3s 自动回落
                        ▼ │
        ┌──────────── 连接（PC 出一双手）─────────────┐
        │ 会话：PC 的会话（共享） · 工具：PC 全套       │
        │ 审批：手机上的审批卡片 · 离线写入联网后并入 PC │
        └─────────────────────────────────────────────┘
```

## 导入管线

1. **采集**（PC）：油猴脚本在已登录的 `chat.deepseek.com` 里调站点内部接口，分页拉会话列表与消息，导出 `herta-import.v1.json`。
2. **传输**：同一 Wi-Fi 下推给手机（扫码带地址与一次性口令）；或存成文件用系统分享打开。
3. **归一**：`{sessionId, title, startedAt, messages:[{role, text, at}]}`，去重键 `sha256(sessionId + 首条时间 + 条数)`。
4. **落地**：归档成只读会话（`origin: "import"`），同时写全文索引。
5. **消化**：dream 管线读取归档，走"值不值得记 → 生成 → 评审 → 修订"，产出进记忆货架。

复述一条硬约束：**她不会因为导入就"记得"**——记忆是 dream 产出的，原文只是原料。

## 已知风险

- **CORS**：原生通道能绕，但要在真机验（M1 卡点）。
- **非公开契约**：油猴脚本依赖 DeepSeek 站点内部接口，随时可能失效；脚本必须"坏了能说清楚"，不能静默空导出。
- **重写的代价**：v0.1 已验的 dream 与复核两道链路作废，M1/M2 要重建测试。
- **音色落差**：离线合成是通用嗓子，不是她的。
- **素材授权**：语音、preset、图标沿用 dsh-herta 的 NOTICE / THIRD-PARTY 边界。
