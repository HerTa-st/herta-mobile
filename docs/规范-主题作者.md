# 主题作者规范（草案 · v1）

> 面向想给 Herta 做主题的人。**契约版本 1** · 写于 2026-11-04
> 状态：v1 已落地（B10，App **0.32.0+**）。表中的 `data-part` 锚点已是契约；后续只会新增，不删不改名。
> 参考实现：[themes/paper](../themes/paper/)（官方示范主题「纸面」）

---

## 0. 一句话

主题是一份 zip，里面是一张身份证（`skin.json`）和一份 CSS（`theme.css`）。你只能改样式，不能改结构，也不能执行任何代码。

---

## 1. 主题是什么，不是什么

**是**：一套观感。配色、圆角、描边、阴影、留白、字体族、纸纹、渐变——凡是 CSS 能画出来的，你都能改。

**不是**：

- **不是一个插件**。主题包不能含 `.js` / `.wasm` / `.node`，App 不会执行主题里的任何代码。
- **不能改 DOM 结构**。你不能新增节点、不能改信息架构。想让某块东西换位置，用 `grid` / `order` / `position` 在样式层做。
- **不能覆盖用户亲手设的东西**。见第 6 节。

---

## 2. 包结构

```
paper.zip
├── skin.json     必需，身份证
├── theme.css     必需，样式本体
└── assets/       可选，字体与图片（只允许被 theme.css 以相对路径引用）
```

约束：

- 必须是 zip，**不超过 4 MB**；根目录直接放 `skin.json` 与 `theme.css`（不要多套一层目录）
- `theme.css` **不超过 256 KB**
- `assets/` **不超过 2 MB**，且只能含 `.woff2` `.png` `.jpg` `.webp` `.svg`

---

## 3. skin.json

```json
{
  "id": "paper",
  "name": "纸面",
  "author": "HerTa",
  "version": "1.0.0",
  "minAppVersion": "0.32.0",
  "contract": 1,
  "description": "米白暖纸底 + 墨绿强调，白天像一本册子。"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 小写字母、数字、连字符；全小写；建议 `<作者>-<主题名>` |
| `name` | 是 | 显示名，会出现在主题列表里 |
| `version` | 是 | 语义化版本 |
| `minAppVersion` | 是 | 低于此版本**拒绝安装**并说明原因 |
| `contract` | 是 | 契约版本，当前只认 `1` |
| `author` / `description` | 否 | 用于列表展示 |

---

## 4. theme.css 的规则

**可以做**

- 覆盖任意 CSS 变量（`--ink` `--accent` …）——这只是写 CSS 的一种省事方式
- 按锚点写任意选择器：`[data-part="message-bubble"] { … }`
- 用 `grid` / `order` / `transform` / `position` 重排、变形、隐藏装饰

**不可以做**

- ❌ `@import`（会把加载顺序交给你自己的远端）
- ❌ `url(http://…)` / `url(https://…)`（主题必须离线可用，也不能做追踪）
- ❌ 引用 `.class` 作为**唯一**依赖——class 名属于内部实现，随时会变
- ❌ 在主题里试图覆盖用户设置（App 会在你的 CSS 之后追加用户覆盖层，你抢不过）

---

## 5. 锚点表

这些 `data-part` 属性是**契约**：App 承诺不删不改名。class 名不构成任何承诺。

| 锚点 | 是什么 | 状态 |
|---|---|---|
| `app` | 应用最外层容器 | 已定 |
| `splash` | 开屏 | 已定 |
| `rail` / `rail-item` | 左侧轨道与其中一项 | 已定 |
| `topbar` / `presence` / `mood` | 顶栏 / 行踪 / 心情 | 已定 |
| `feed` / `day-divider` | 消息流 / 日期分隔 | 已定 |
| `message` | 一条消息的容器 | 已定 |
| `message-bubble` | 气泡本体 | 已定 |
| `message-thought` | 她的「想」块 | 已定 |
| `message-actor` | 动作（括号斜体那行） | 已定 |
| `message-time` / `message-usage` | 时间 / token 徽章 | 已定 |
| `message-note` | 系统旁白 | 已定 |
| `message-card` | 转播卡、提醒卡这类整块卡 | 已定 |
| `composer` / `composer-input` / `composer-action` | 输入条 / 输入框 / 每个按钮 | 已定 |
| `panel` | 模块页的通用卡面（币 / 播报 / 记忆 / 主题包） | 已定 |
| `empty-state` | 空态块 | 已定 |

**必须同时写亮色与暗色两套**：`:root[data-theme="light"]` 与 `:root[data-theme="dark"]`。只写一套的主题在另一半会被判为不合格。

---

## 6. 优先级

层叠顺序固定，从下到上：

1. App 内置样式
2. **你的 `theme.css`**
3. **用户显式设置**：当前的脸（头像）/ 聊天背景 / 日间夜间 / 字体

也就是说：用户亲手设过的东西，你盖不掉。这是刻意的——**主题不能替用户做决定**。

---

## 7. 版本与兼容

- `contract` 变了 = 破坏性变更，App 会拒绝 `contract` 不匹配的包
- App 新增锚点不算破坏性变更；**删除或改名**才算
- `minAppVersion` 不满足时，App 拒绝安装并说清「这个主题需要 X 以上」
- `theme.css` 里少写某个 CSS 变量时，该变量继承 App 内置值（所以老主题不会因为 App 新增变量而失效）
- `skin.json` 的必填字段不能缺；只有 `author` / `description` 可省

## 8. 分发

**一期：链接导入**

把主题打成 zip，放到任何可以直接下载的地方（GitHub Release 资产、仓库 raw 链接），把链接发出去。别人在 App 里粘贴链接即可安装。

**二期：索引**

所有主题提交到一处 `themes.json`，App 拉索引、浏览、一键安装。提交方式见仓库 README。

---

## 9. 上架要求（二期索引）

- 仓库公开，带 `LICENSE`
- 一张 390×844 的截图
- README 写清：改了什么、依赖哪个版本的 App
- **不得包含可执行文件**
- 命名：`<作者>-<主题名>`

---

## 10. 自查清单

- [ ] `skin.json` 六个必填字段齐全，`id` 全小写
- [ ] 亮色与暗色两套都写了
- [ ] 只用 `data-part` 锚点，没把 class 当唯一依赖
- [ ] 没有 `@import`、没有外链 `url()`
- [ ] 包内没有 `.js` / `.wasm`
- [ ] zip ≤ 4 MB，`theme.css` ≤ 256 KB，`assets/` ≤ 2 MB
- [ ] 在真机上装过一次，切回内置主题不残留
