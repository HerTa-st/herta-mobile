# Herta 手机端 · 黑塔币 v1 设计

> 2026-10-29 定稿。按 `docs/设计-v1.md` 的规矩：这里只记**已经和用户敲定的决策**与**验收标准**；技术实现细节写在对应模块里。
> 一条规矩：这里没写的，做的时候不许默默假设——要么问，要么先补进这份文档。

## 一句话

手机端里加一个**黑塔币（HTC/USDT）行情小模块**：每天 9:30 开盘（工作日 09:30–11:30 / 13:00–15:00），行情与网页同源；进来能看分钟 K、签个到、看自己的持仓。币的「货币」部分放在 app 里自己算；v1 不接她、不做交易。

## 决策表

| # | 决策 | 结论 | 代价 / 备注 |
|---|---|---|---|
| 1 | 模块定位 | **独立小模块**（聊天之外）；长期目标是群友联机 | 先轻量跑通，不占聊天主流程 |
| 2 | 入口 | 抽屉里加「黑塔币」入口；**只做抽屉入口**，不加底部 Tab | 不动 app 导航结构 |
| 3 | 页面形态 | **全屏页面**，左上角返回聊天 | 复用 App.tsx 现有全屏视图模式 |
| 4 | 行情数据源 | **阿里云函数计算 FC 提供 JSON 接口**；算法与网页同源 | 需要单独部署维护 FC；断网只能看缓存 |
| 5 | 行情粒度 | 完整分钟 K（240 根/场）；打开立即拉取，**每 30 秒轮询** | JSON 几 KB 级；交易时段与网页一致 |
| 6 | 时间口径 | 跟真实时间：工作日 09:30–11:30 / 13:00–15:00；其余时段显示上一场 | 和网页同一根 K 线 |
| 7 | 签到时间 | 每天 **09:30 后**可签；**必须联网**（以服务器时间判断） | 防改手机时间 |
| 8 | 签到奖励 | 连续签到：第 1 天 +10、第 2 天 +20、之后每天 +5，**第 8 天起 +50 封顶**；断签重置 | 即 10 / 20 / 25 / 30 / 35 / 40 / 45 / 50… |
| 9 | 签到入账 | 奖励按**签到当时实时价**入账（记录奖励与价格） | v1 不并入成本价 |
| 10 | 离线行为 | 离线**只能看缓存行情**，签到不可用；页面标「离线」 | 不做离线签到补交 |
| 11 | 初始资产 | 首次进入黑塔币页时送 **1000 HTC**，成本价 = 当前展示场次的开盘价 | 只发一次，记在本地 |
| 12 | 持仓口径 | 持仓卡显示：数量、当前市值、今日盈亏（较昨收）、成本价 | 成本价 v1 固定为首次入账价（简化，见风险） |
| 13 | 通知 | 每天 **09:30** 本地通知：开盘 + 可以签到 | 需系统通知权限；仅工作日 |
| 14 | 与 Herta | **v1 不接**；v1.1 给她加「查黑塔币行情 / 我的持仓」的工具 | 不做每轮系统提示注入 |
| 15 | 数据与同步 | v1 单机（IndexedDB）；**v1.2** PC 同步；**v2** 群联机 | 沿用现有备份导出机制 |
| 16 | 版本路线 | v1 行情+签到+持仓 → **v1.1** 她的工具 + 交易入口/交易 → **v1.2** PC 同步 → **v2** 群联机 + 聊天经济 | 交易与聊天经济后置 |
| 17 | 视觉 | 延续 app 现有界面语言（浅色青白主题），不照搬网页暗紫终端 | 见「视觉」一节；暗色版本留待用户另行确认 |
| 18 | 页面板块（v1） | 价格条 → 分钟 K + 成交量 → 持仓卡 → 签到卡 → 交易入口占位 | 交易按钮不可点，文案「交易功能开发中」 |

## 架构

```
阿里云 FC（Node.js）
  GET /api/daily  ── JSON（同一套确定性算法）
        ▲
        │ HTTPS（30s 轮询 / 打开即拉）
        │
apps/phone
  components/CoinView.tsx     全屏页面（价格条 / 图表 / 持仓 / 签到 / 交易占位）
  coin/useCoin.ts             行情拉取 + 缓存 + 轮询 + 签到状态
  coin/coin-storage.ts        IndexedDB：钱包 / 签到记录（新 store）
  coin/chart.ts               Canvas 分钟 K 绘制（沿用网页的视觉逻辑，配色换成她的）
  coin/notify.ts              每日 09:30 本地通知（Capacitor LocalNotifications）
packages/coin                纯逻辑，Node 里可测
  signin.ts                   连签曲线 / 断签重置 / 入账计算
  wallet.ts                   持仓市值 / 今日盈亏 / 成本价
  api.ts                      接口类型与客户端（含 serverTime）
  test/coin.test.mjs          单测
```

**为什么有 `packages/coin`**：签到曲线、盈亏公式、接口类型都是纯逻辑，放 core 里会和聊天/记忆耦合；单独一包以后群联机、PC 同步也能复用。

**算法同源**：网页端（`phantom-market/app.js`）的密钥哈希、日线链、分钟 K、桥接、新闻事件逻辑是唯一事实来源。FC 里放一份 Node.js 同源实现，并用「测试向量」保证两边输出一致（见验收 1）。

## API 契约（FC）

```http
GET {COIN_API_BASE}/api/daily
Accept: application/json
```

返回（版本 1）：

```jsonc
{
  "version": 1,
  "serverTime": "2026-10-29T10:15:30+08:00",   // 服务器时间，签到只认它
  "market": {
    "name": "黑塔币",
    "code": "HTC",
    "pair": "HTC/USDT",
    "sessionDate": "2026-10-29",
    "sessionNumber": 214,
    "status": "trading",                        // trading | preopen | lunch | closed | weekend
    "statusLabel": "交易中 · 上午",
    "prevClose": 88.98,
    "open": 89.03,
    "high": 90.03,
    "low": 88.42,
    "close": 89.87,
    "changePct": 1.002,
    "volume": 77000,                            // 手 / HTC
    "turnover": 6871800,                        // USDT
    "revealed": 45,                             // 已揭示分钟数
    "partial": 0.5,                             // 当前分钟进度 0~1
    "keyFingerprint": "4CDBB70C",
    "bars": [                                   // 仅推送已揭示的分钟 K（含当前部分 K）
      { "t": 0, "o": 88.99, "h": 89.18, "l": 88.84, "c": 89.04, "v": 1051 },
      { "t": 45, "o": 89.04, "h": 89.10, "l": 88.97, "c": 89.02, "v": 620, "partial": true }
    ]
  }
}
```

约定：

- **CORS**：允许 `https://localhost` / `capacitor://localhost`（Capacitor WebView origin）。若线上不通，走 app 现有原生 HTTP 通道（`transport.ts` 已为 DeepSeek 做过同类绕行），不新增后端。
- **不缓存**：`Cache-Control: no-store`；app 自己缓存最后一次成功响应（IndexedDB）。
- **错误态**：非 200 或 JSON 非法时，app 显示「行情暂不可用」，有缓存则展示缓存 + 「离线」标记。
- **v1 不提供签到接口**：签到的「联网」指**拉一次 `/api/daily` 拿 serverTime**，本地记录签到；单机阶段不需要服务端账号与存储。v2 群联机再上服务端账本。
- `bars` 只含已揭示部分，app 不自己补未来数据。

## 数据模型（IndexedDB）

现有库 `herta`，`DB_VERSION = 3`（sessions / memories / kv / stickers）。新增 **`coin` store**，版本升到 **4**，键固定：

```ts
// coin store
interface CoinWallet {
  version: 1;
  holdings: number;        // HTC 数量，初始 1000
  costPrice: number;       // 首次入账时的价格（v1 简化成本）
  initialAt: string;       // 首次激活时间（ISO）
  lastSign: {
    date: string;          // 服务器场次日期 YYYY-MM-DD
    streak: number;        // 连续天数
    price: number;         // 签到入账价
    reward: number;        // 本次奖励 HTC
  } | null;
  history: Array<{ date: string; reward: number; price: number }>; // 只保留最近 60 条
  updatedAt: string;
}
```

- 首次打开：读接口 → 若 store 无钱包 → 写入 `holdings=1000, costPrice=market.open`。
- 签到：追加 `history`、更新 `holdings += reward`、`lastSign`、`streak`。
- 断签判定：`lastSign.date` 与服务器场次日期间隔超过 1 个交易日 → `streak` 从 1 重算（按工作日判断）。

## 页面与交互（v1）

**抽屉入口**
- `DrawerActions` 新增 `openCoin(): void`；抽屉里「新的对话」下方加一行按钮「黑塔币 HTC」，右侧显示 `+1.00%` 小字（有缓存时）。
- 不新增底部导航、不改聊天主界面。

**全屏页面（CoinView）**
1. 顶部返回 + 标题「黑塔币 · HTC/USDT」；右侧状态徽标：交易中 / 盘前 / 午休 / 已收盘 / 休市（周末）。
2. 价格条：现价、涨跌幅、今开/最高/最低、成交量；灰色小字「行情与网页同源 · 30s 刷新」。
3. 分钟 K 图：240 格时间轴（09:30–11:30 / 13:00–15:00，午休分隔线），红涨绿跌（用她的浅色版配色），成交量副图；十字光标可看单根 OHLC（触屏长按/拖动）。
4. 持仓卡：持有数量、当前市值、今日盈亏（较昨收，红/绿）、成本价。
5. 签到卡：09:30 前显示「09:30 开盘后可签到」；可签时按钮「签到 +10 HTC」（按连签曲线）；已签显示「今日已签到 · 连续 N 天 · 明天 +XX」；离线时按钮禁用并提示「签到需要联网」。
6. 交易入口占位：按钮「交易功能开发中」，不可点（v1.1 再打开）。

**文案口吻**：以 app 现有文案为准（简洁、克制、带一点她的语气），不做每轮剧情。签到成功可以有一句随机她的吐槽（本地文案，不调模型）。

## 视觉

**事实**：app 现有主题是浅色（`styles.css`：青白渐变打底、白卡片、`--accent:#6fa8ad`；注释明确说深紫「不像她」）。因此：

- 黑塔币页面沿用 app 浅色卡片风：`--card` 白卡、`--ink` 正文、`--line` 细线；
- 行情涨跌用她的浅色版红/绿：涨 `#d96a7a`、跌 `#4f9d8a`（与聊天里的粉/青呼应，不刺眼）；
- 均线/均价线：`#d9a66a` / `#6fa8ad` / `#a58ac9`；
- 图表网格 `#e6eef0`，坐标文字 `--muted`；
- **不**把网页那张暗紫终端照搬进 app（如需暗色版本，单独确认后只换调色板）。

## 与她 & 后续版本

- **v1 不接**：她不知道黑塔币，聊天不受影响。
- **v1.1 她的工具**：新增只读工具（`coin_quote`）：返回现价、涨跌幅、持仓数量、市值、今日盈亏、今日是否已签到。她按人格自行决定要不要调、怎么吐槽。不做每轮系统提示注入。
- **v1.1 交易**：交易入口打开，买卖/持仓成本/手续费规则单独出一份设计（交易经济必须和签到分开定，别混在 v1）。
- **v1.2 PC 同步**：钱包/签到随 backup 一起走；经 M4 网关同步到 PC。
- **v2 群联机 + 聊天经济**：账号/服务端账本、排行榜、转赠、聊天赚币；需要服务器方案（单独设计）。

## 验收标准（可证伪）

1. **算法同源**：给定固定输入（如 `2026-10-29` 10:15:30），网页与 FC 的 `sessionDate / prevClose / open / close / revealed / bars.length` 完全一致（FC 仓库存测试向量）。
2. **有网**：进入黑塔币页 5 秒内出 K 线；停留 60 秒后，图表至少前进 1 根或当前价变化（30s 轮询生效）。
3. **断网**：显示最后一次缓存 + 「离线」标记；签到按钮禁用并提示需联网。
4. **签到时间**：09:30 前不可签；09:30 后可签；同一天重复点击被拒（提示已签到）。
5. **连签曲线**：连续签到第 1~8 天奖励依次为 10/20/25/30/35/40/45/50；断签后回到 10。
6. **防改时间**：把手机时间改到次日，签到提示「以服务器时间为准，未到下一场」。
7. **持仓口径**：初始 1000 HTC；签到后数量增加；市值 = 数量 × 现价；今日盈亏 = 数量 ×（现价 − 昨收）；成本价 = 首次入账价。
8. **通知**：授权后工作日 09:30 收到一条本地通知；点击打开黑塔币页；未授权时不报错、页面有开启提示。
9. **持久化**：杀进程重开，钱包与签到记录仍在；备份导出包含 coin store（若 v1 备份暂不包含，需在 UI 明示）。
10. **工程**：`npm run typecheck` 与 `npm test` 绿；Android 真机跑通（非仅浏览器）。
11. **UI**：与 app 浅色主题一致，无横向滚动、无内容遮挡；手机竖屏与横屏都不破版。

## 风险与欠债

- **FC 未部署、域名未就绪**：v1 真机验收前必须先把 FC 接口跑通；开发阶段用 mock（`COIN_API_BASE` 指向本地假数据），mock 不能带进发布包。
- **算法漂移**：网页与 FC 必须同一份算法规格；上线后每次改算法要同步更新测试向量，否则「网页发股线、app 算货币」会对不上。
- **成本价简化**：v1 只用首次入账价，签到不改变成本价；交易上线（v1.1）时改为加权成本，需要迁移旧数据。
- **改时间防不住本地钱包**：本地数据可被清/改，单机阶段不追求防作弊；v2 群联机再上服务端账本与签名。
- **通知调度**：Android 各版本通知权限/后台限制不同，需真机验证工作日 09:30 的重复排程（可能需要在每次开 app 时续排下一条）。
- **视觉待确认**：若用户实际想要「黑白紫暗色版」而不是 app 现有浅色主题，只改调色板，但要先确认。

- **交易入口占位文案**：沿用「交易功能开发中」。

## 实现补充口径（设计没写死、实现时定下的）

- 签到只在**工作日**、服务器本地时间 **≥ 09:30** 后可签；周末不可签（显示「休市 · 下一场开盘后可签」）。
  签到目标场次 = 服务器本地日期（必须为交易日），断签判定用该日期与 `lastSign.date` 的下一个交易日比较。
- 行情缓存与轮询：页面打开即拉，之后每 30s 一次；页面关闭即停；失败回退最后一次成功响应并标「离线」。
