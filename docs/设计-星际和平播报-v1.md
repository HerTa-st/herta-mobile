# Herta 手机端 · 星际和平播报 v1 设计

> 2026-11-02 定稿。按 `docs/设计-v1.md` 的规矩：这里只记**已经和用户敲定的决策**与**验收标准**；技术实现细节写在对应模块里。
> 一条规矩：这里没写的，做的时候不许默默假设——要么问，要么先补进这份文档。

## 一句话

手机端加一个**星际和平播报**：她每天替你挑 3–7 条真新闻、每条写一句她的评，包装成「《星际和平播报》第 N 期 · 空间站「黑塔」转播」。打开是一个独立页，不占聊天主流程；偶尔会多一条标明「本台虚构」的彩蛋。

## 决策表

| # | 决策 | 结论 | 代价 / 备注 |
|---|---|---|---|
| 1 | 定位 | **独立模块**（聊天之外）；桌面端后续复用同一份契约 | 先轻量跑通，不动会话主流程 |
| 2 | 落地端 | **手机端 herta-phone 先行**；dsh-herta 二期 | 手机端已有搜索、通知、IndexedDB |
| 3 | 页面形态 | **独立全屏页**（照黑塔币 / 记忆的做法）；当天一期置顶，历史期往下 | 不新增会话类型 |
| 4 | 入口 | 每日「播报提示」消息（气泡 + 「查看播报」按钮，落在当时打开的会话）+ 抽屉常驻入口 + 08:30 本地通知 | 三个入口，同一天只发一条提示 |
| 5 | 内容 | **真新闻为主**；每条有真实来源、可点回原文 | 不把编的新闻混进来 |
| 6 | 条数 | 目标 **5 条**，**3–7 条**浮动；宁缺毋滥 | 没货就少发，不硬凑 |

| 11 | 评 | 每条**一句**她的评，是判断 / 吐槽，不是摘要；走人格层语气 | 长度上限 40 字左右 |
| 12 | 通知 | 每天 **08:30** 本地通知（重复日排程）；标题「黑塔」，正文「今天的星际和平播报到了。」；点通知进播报页；可关 | 照黑塔币 `coin/notify.ts` 的写法 |
| 13 | 期号 | **按实际生成递增**，错过不占号 | 第 1 期从首次生成开始 |
| 14 | 历史 | **永久保留**（纯文本）；设置里一键清空；旧期离线可读 | 封面不落盘，存储压力小 |
| 15 | 失败 | 没网 / 搜索失败 / 没有合格候选：明说「今天这期还没出来」+ 重试；**不编新闻** | 旧期照常显示 |
| 16 | 互动 | 「原文」跳原文；「让她再多说两句」回聊天并带引用，她接话 | 追问落在当前会话 |

| 20 | 视觉 | 延续浅色青白；标题 `《星际和平播报》 第 N 期 · 空间站「黑塔」转播`；日期条 `今天 11月2日 · 5条` | 照截图的气质，不照搬大图 |
| 21 | 版本 | v1 手机单机 → v1.1 桌面 / 云预生成（按需） | 先把手机端闭环跑通 |

| 23.1 | 版面 | 照桌面信息流：报头「《星际和平播报》/ 第 N 期 · 空间站「黑塔」转播」→ 日期行「今天 11月2日 · 5 条」→ 头条（大封面 + 标题/摘要/关系 chip）→ 编号行 01/02…（小封面）→ 每条下面「黑塔」批注 → 尾行「以上为本期全部内容」 | 与聊天里的转播卡是两种东西 |
| 23.2 | 关系 chip | 每条带一句 why（如「你关注人工智能」）；模型没给就按关注标签补 | 桌面卡片的同一个字段 |
| 24 | 播报提示的形态 | 聊天里是**转播卡**（左侧色条 + 「星际和平播报 · 第 N 期」+ 查看播报），**不是对话气泡** | 与她说出口的话分开；真机上被拍到她把提示当成开拓者的消息回 |
| 25 | 提示的转录 | 序列化成**系统旁白**（「她把第 N 期递过去了，不是开拓者说的话」），不算她说过的话；提示之后、他开口之前 proactive 不插话 | 同 24 的坑：写成「我 说」她会自己接茬 |

## 架构

```
apps/phone
  components/BroadcastView.tsx   全屏播报页（当天一期 + 历史 + 设置）
  components/BroadcastNotice.tsx 聊天里的转播卡（不是对话气泡）
  components/BroadcastReader.tsx 点开一条的阅读页（要点 + 短稿）
  broadcast/reader.ts            抓原文 → 洗正文 → 压成要点/短稿
  broadcast/generate.ts          搜索 → 筛 → 写评 → 结构化
  broadcast/useBroadcast.ts      状态机：今天有没有期 / 生成 / 缓存 / 失败
  broadcast/storage.ts           IndexedDB store broadcast
  broadcast/notify.ts            每天 08:30 本地通知 + 路由
packages/core/src/broadcast.ts   纯逻辑：去重 / 期号 / 校验 / 彩蛋规则
packages/core/test/broadcast.test.mjs
```

**为什么生成放手机**：手机端本来就能直连 DeepSeek（`transport.search` + LLM），不需要 PC；密钥留在手机。代价是 app 关着时不能预生成——08:30 通知照响，点开生成几秒。

## 数据模型

```ts
interface BroadcastIssue {
  id: string;        // 2026-11-02
  no: number;        // 期号，按实际生成递增
  date: string;      // 2026-11-02
  createdAt: string;
  items: BroadcastItem[];
  status: "ready" | "failed";
  error?: string;
}

interface BroadcastItem {
  id: string;        // hash(url) 或 uuid
  source: string;    // 网易
  domain: string;    // 163.com
  title: string;
  summary: string;   // 2–3 行
  url: string;
  publishedAt?: string;
  tag?: string;      // 关注标签
  comment: string;   // 她的评
  egg?: boolean;     // 彩蛋：最后一条，不计入 3–7
}
```

## 生成流程

1. 08:00 后第一次打开 / 回前台：查今天的 issue；有 → 跳过；失败 / 没有 → 生成。
2. 用关注标签拼 2–4 条搜索 query，`transport.search` 拉候选（标题 / URL / 摘要）。
3. 合并去重（URL），按域名黑名单排除内容农场 / 聚合站，优先原始媒体。
4. 一次 LLM 调用：给候选清单，让她选 3–7 条 + 每条一句评 + 可选一条彩蛋，返回严格 JSON。
5. 校验 JSON（条数、URL、必填字段）；失败重试一次，再失败落 `failed`。
6. 落库；往当时打开的会话追加一条「播报提示」消息（带「查看播报」按钮），同一天只加一次。

## 页面

- 头部：`《星际和平播报》 第 N 期 · 空间站「黑塔」转播`，日期条 `今天 11月2日 · 5条`。
- 条：媒体 favicon + 来源 + 时间；标题；2–3 行摘要；关注标签；她的一句评；「原文」「让她再多说两句」。
- 彩蛋：最后一条，`本台虚构` 角标 + 不同底色，不提供原文链接。
- 历史：当天一期置顶，往下是以前的期；点期头展开。
- 失败：`今天这期还没出来` + 重试按钮；旧期照常。
- 08:00 前：显示 `今天的播报 08:00 后才出`，另给一个 `现在就来一期` 手动按钮（自动逻辑不变，方便第一次验证）。
- 设置（页内齿轮）：关注标签增删、通知开关 / 时间、清空播报历史。

## 通知与入口

- 08:30 本地通知（Capacitor LocalNotifications，重复日排程，照 `coin/notify.ts`）；通知 id 固定；`extra.route = "broadcast"`；点通知打开播报页。
- 聊天里的「播报提示」：`herta` 气泡 + 按钮；落在当时打开的会话（和主动消息同一条路）；同一天只发一次。
- 抽屉：「播报」常驻入口；有新期未读时亮红点。

## 边界（必须守住）

- **不编新闻**：搜索失败 / 没有合格候选就明说，宁可少发。
- **彩蛋必须可辨**：角标 + 底色 + 无原文链接；每期最多一条。
- **隐私**：搜索 query 与新闻内容只走 DeepSeek 搜索 / 模型；不上传本地会话。
- **记忆**：播报内容不进 NMS 的 pending_turn（不是聊天）；「让她再多说两句」那一轮才进。

## 验收标准

1. 08:00 后打开，当天一期生成 3–7 条真新闻；每条有来源、有可打开的原文；目标 5 条，没货不硬凑。
2. 彩蛋最多一条、在最后、有「本台虚构」角标和不同底色、无原文链接；真新闻条数仍是 3–7（彩蛋额外）。
3. 关注标签默认 人工智能、游戏；设置可增删；标签变化影响下一次抓取；NMS 不会自动改标签。
4. 08:30 通知：标题「黑塔」，正文「今天的星际和平播报到了。」；点通知进播报页；设置里能关。
5. 每日「播报提示」消息带「查看播报」按钮，落在当时打开的会话；点按钮进播报页；同一天不重复。
6. 播报页：标题 / 期号 / 日期 / 条数正确；当天置顶，历史可翻；旧期离线可读。
7. 没网 / 搜索失败：显示「今天这期还没出来」+ 重试；不出现编的新闻；旧期正常。
8. 「让她再多说两句」：回聊天并带引用，她接话。
9. 期号按实际生成递增，错过不占号。
10. `npm test`（新增 broadcast 纯逻辑测试）与 `npm run typecheck` 通过；浏览器 dev 可跑，原生通知在 APK 里验。
11. 清空历史：设置里一键清空，IndexedDB broadcast store 清空；当天不再自动补做；备份包包含播报期（同一期不重复写）。
