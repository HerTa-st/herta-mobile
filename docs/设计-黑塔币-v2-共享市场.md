# 黑塔币 v2 · 共享市场设计（草稿）

> 2026-10-29 起草。按 `docs/设计-v1.md` 的规矩：没敲定的不默默假设，待确认项列在最后。

## 一句话

v1 是单人看行情 + 签到；v2 让群里所有人都进同一个市场：**每个人的买卖按净买入实时推动价格**，持仓、USDT、成交都记在服务端，网页/App 看到的是同一个价格。

## 已敲定的决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | 身份 | 手填**昵称/QQ 号**（1–20 字），服务端按它记账（v1 不做防冒充） |
| 2 | 价格 | 确定性基础行情 ×（1 + 当日净买入冲击）；**1 万 HTC 净买入 ≈ +0.5%**，单日冲击上限 ±20% |
| 3 | 交易 | 市价买卖；手续费 **0.3%**（USDT 扣）；同一身份 **5 秒 1 单**；每天**买、卖各最多 5 次**；单笔上限 **10,000 HTC** |
| 4 | 结算 | 每个交易日 09:30 换场时，净买入、交易次数归零 |
| 5 | 排行榜 | 按持仓市值排序，展示前 20 名 |
| 6 | 服务端 | 继续用阿里云 FC（不买服务器）；**不开表格存储**，共享状态存现有 OSS Bucket |

## 技术方案

```
App / 网页
   │ HTTPS
   ▼
阿里云 FC（coin-api 函数，扩展路由）
   │ 读改写（带锁）
   ▼
OSS <bucket>  Bucket
   state/coin.json    共享状态（市场 + 所有用户）
   state/coin.lock    互斥锁（forbid-overwrite 创建，3 秒 TTL）
```

- **为什么用 OSS 存状态**：不用再开表格存储/数据库，零额外服务与费用；状态就一个 JSON（几百人也就几十 KB），加锁后读改写是安全的。
- **并发**：请求先抢占 `state/coin.lock`（`x-oss-forbid-overwrite`），抢不到退避重试；锁超过 3 秒视为死锁可抢占；处理完删除锁。
- **权限**：FC 函数需要能读写这个 Bucket。推荐给函数配「执行角色」（RAM 角色 + `AliyunOSSFullAccess`），函数里用 `context.credentials`（STS）；也可退而求其次在函数环境变量里放一个只授权该 Bucket 的 AccessKey。

## API 契约（v2 新增）

```http
GET  /api/state?user=QQ昵称
POST /api/trade        {"user":"昵称","side":"buy|sell","amount":1000}
GET  /api/leaderboard
POST /api/signin       {"user":"昵称"}        // 若签到迁到服务端（待确认）
```

`GET /api/state` 返回：

```jsonc
{
  "serverTime": "2026-10-29T13:40:00+08:00",
  "market": {
    "sessionDate": "2026-10-29",
    "status": "trading",
    "basePrice": 91.6507665,          // 确定性行情算出的基准价
    "price": 92.0100,                 // 叠加净买入冲击后的共享价
    "changePct": 3.40,                // 相对昨收（含冲击）
    "netBuy": 7200,                   // 当日净买入 HTC（买入-卖出）
    "volume": 218362                  // 当日成交量 HTC
  },
  "user": {
    "name": "梦源",
    "htc": 1000,
    "usdt": 100000,
    "cost": 89.03,
    "todayBuy": 1,
    "todaySell": 0
  },
  "limits": { "feeRate": 0.003, "maxOrder": 10000, "buyPerDay": 5, "sellPerDay": 5, "cooldownMs": 5000 },
  "leaderboard": [ { "name": "A", "value": 123456 }, ... ]
}
```

`POST /api/trade` 返回成交价、手续费、成交后持仓；错误统一 `{"error":"...","message":"人话"}`。

## 验收标准

1. 两个不同昵称同时买卖，价格实时变化且双方看到同一个价。
2. 5 秒内连点两次 → 第二次被拒绝；当天买卖各超过 5 次 → 被拒绝。
3. 余额不足 / 持仓不足 → 被拒绝且余额不变；手续费按 0.3% 扣。
4. 09:30 换场后净买入、次数归零。
5. 杀掉 App 重开，服务端持仓/余额一致。
6. 并发 10 个请求同时下单，状态不丢单（锁生效）。

## 已确认（2026-10-29 14:20）

1. **初始资产**：1,000 HTC + 100,000 USDT，填昵称进入共享市场即自动开户。
2. **签到迁到服务端**（`POST /api/signin`）；单机模式下本地签到保留，两边不混用。
3. **本地钱包合并**：首次进入共享市场时把单机钱包 HTC 一次性并入（`POST /api/claim`，每人仅一次、上限 100,000 HTC）。
4. **身份**：黑塔币页顶部输入昵称 / QQ 号；留空 = 单机模式，填了 = 共享市场。
5. **交易面板**：持仓卡下方（数量、预计金额/手续费、买入/卖出、今日剩余次数）。
6. **FC 授权**：执行角色（RAM 角色 + OSS 读写 `state/*`），函数用 `context.credentials`。
