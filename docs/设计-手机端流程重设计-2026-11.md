## 0. 一句话

手机端**不是结构错了**——左轨早就把每天要做的事放在一级；错的是**同一件事散在好几个入口**，以及**没有页面栈**所以每处都得自己造返回。这次把首次流程做成一等状态、把散掉的东西按「就地」归位、把缺的那几步补上，其余不动。

---

## 1. 口径与边界

- **只动产 UI 与导航。** 会话 / 记忆 / 黑塔币的数据、协议、存储一律不动，升级后一条记录都不能丢。
- **分发走自建渠道**（GitHub Release + 直接装 APK），按商店标准自律。见 [ADR-0003](adr/0003-self-hosted-distribution.md)。
- **预算按天算。** 每天约 ¥10 的开工额度，一批一天，**每批收尾必须能打出可安装包**。
- **对象是陌生人也能装**，但重设计的钱花在你自己的日常上；首次流程只做到「不死路 + 第一句话能成」这一档。

## 4. 首次流程

### 4.1 未接通

装好 App、能打开，但没有可用 Key 的状态。它是一个**被设计过的状态**，不是一个错误。

- 只有聊天被锁；记忆 / 黑塔币 / 备份照常可用
- 输入框改成引导，不再弹「先填 API Key」的红字
- 主界面常驻一条「她还没接上，点这里填 Key」
- 播报页空态：「今天还没有；接上她才会说话」

### 4.2 Key 验证

第 2 步填完自动发一个最小请求：过了给绿点，没过说人话（Key 不对 / 网络不通 / 没余额），**不挡继续**，只记下状态。

### 4.3 引导

五步不变（怎么称呼 / 填 Key / 她能做什么 / 允许通知 / 电池白名单），只改文案——重点是把「你现在不做也行」说清楚。

### 4.4 开屏

- 距上次展示 **≥12 小时**才播；只算冷启动
- 动画换新：**铺满屏幕的 ASCII 竖流，不画角色剪影**；流完交叉淡入主页（原型见 [splash-vertical-flow.png](prototypes-2026-11/splash-vertical-flow.png)）。竖屏缩放下剪影只会糊成一团，所以刻意不留。
- 这批先落频次控制与机制，动画随后替换

## 5. 日常流程（四根）

> 骨架那一根的顺序理由见 [ADR-0002](adr/0002-page-stack-before-consolidation.md)。

### 根①「散」→ 就地原则

一条设置放进它所描述的那件事的页面里：

| 现在在哪 | 归到哪 |
|---|---|
| 设置页「她」组：深睡 / 深睡上限 | 记忆页 |
| 记忆页设置 tab：语气参数 / 重写语气 | 记忆页（保留，就地） |
| 她能做什么（11 项权限） | 保留为独立页，设置页只留一个入口 |
| 播报页内 ⚙：关注标签 / 提醒时间 | 播报页正文，不再藏在齿轮后 |
| 设置页 | 只留：API Key / Base URL / 模型 / 视觉模型 / 省 token / 主题 / 备份迁移 / 数据统计 |

### 根②「步」→ 输入区重排

发图现在是五步。目标：**回形针一次给出「拍照 / 相册 / 文件」三个明确来源**，选完直接回到输入条预览，不再多一层托盘。

### 根③「死路」→ 能读的文件可删

设置里「给她读的文件」加删除入口，单条删 + 全清。

### 根④「骨架」→ 页面栈 + 路由标识

页面从布尔量改为可压栈的结构，每个页面有稳定 route 标识；通知点进来能落到对应页。

### 根⑤「过程污染了聊天流」

聊天流里应该只有两种东西：**你说的话**、**她说过的话**。过程不该占正文的位置。

| 现在 | 改成 |
|---|---|
| 工具调用在聊天里留一条灰字「（上网查了：…）」 | **聊天里完全不留**，全部只进「设置 → 工具调用记录」。工具旁白本来就是 `kind:"system"` 的块，有 `hidden` 字段——把它藏掉，但**转录与检索仍保留**（别连数据一起删） |
| 她的「想」是一整块青色左边条、常驻展开 | **默认收起成一行「▸ 想了一下」**，点开展开。设计文档原本就写着「想是页边批注，说是正文」——批注不该占正文的位置。展开状态不持久，离开再回来恢复收起 |
| 「（她看到了，没接话）」 | **保留**。这类不是过程日志，是**她的一种反应**；把它收走，聊天会变成一个只会说话的客服窗口 |

### 根⑥「手势：能用系统的就别自己造」

**原则：同一种手指动作只承担一件事。** 长按已经是三个入口的主门（消息 / 会话行 / 图片），不再往上叠滑动层。

| 手势 | 决定 |
|---|---|
| **返回** | **交给系统**：Android 边缘侧滑 + 预测性返回，页面栈跟着走。**不自己拦截**——自造侧滑会和用户肌肉记忆打架 |
| **会话行左滑** | **不做**。长按出菜单已经够了，再开左滑就是同一件事两个入口（正是这次要治的病），而且左滑和「点开会话」手指动作太近，误触删除代价高 |
| **下拉刷新** | **只有行情页和播报页**。聊天页不做（往上翻历史手一滑就触发，而且本来就有「↓ 最新」）；记忆页不做（数据自己长，刷了没变化） |
| **双击 / 摇一摇** | 不用 |
| **无障碍** | 长按是主入口，所以**每个长按动作都要有一个可点、可访问的替代路径**（菜单里也要有入口），不能只有长按能到达 |

## 6. 新功能

### 6.1 头像与背景

- **入口**：设置里新开一组「外观 · 她的样子」，头像、聊天背景、背景作用域三样都收在这一处（外观是跨页面的全局偏好，按「就地」它属于设置；顶栏点头像仍然进这里，保住肌肉记忆）
- **预设像**：程序生成的半调 H 标记——墨底、青色点阵、纸白 H，**不依赖任何立绘素材**（原型见 [avatar-marks.png](prototypes-2026-11/avatar-marks.png)）。48px 桌面尺寸下仍能读出字形，这是选它的硬标准
- 相册自选：走已有相册权限
- **当前的脸**：全应用唯一，历史消息跟着换
- 背景：程序生成预设若干 + 相册自选；作用域做成设置里的二选一（全局 / 按会话），新会话继承全局
- **应用图标**：已替换成 A 的半调 H——墨色背景层 + 半调点阵前景层 + 五档密度的 legacy 方/圆标。**静态替换，不做运行时联动**（运行时只能切换打包时预置的 alias）

### 6.2 缺口

- 发送失败可重发 + 断网提示
- 会话管理：长按会话行 → 重命名 / 置顶 / 多选删除
- 消息级操作：长按 → 复制 / 引用 / 单独重生成
- **她找过我**：见决策 12
- 表情与文件库统一管理入口

---

### 6.3 今日用量（token 账本）

**入口**：设置页「连接」组下一行「今日用量」，点开是整屏明细（按「就地」——用量属于连接这件事）。

**内容**
- **分链路**：主对话 / 复核 / 判心情 / 播报 / 深睡 / 自动语气 / 主动消息 / 读原文
- **全算，含后台**：深睡、自动语气、播报这些你不看着的时候也在花钱，藏起来这个数字就不真
- **输入 / 输出分开**显示，**不折算金额**（金额要填单价、还要处理缓存命中价，先给硬事实）
- **只留当天**：按本地自然日，过零点清零

**为什么必须分链路**：复核那一段的 system 固定 2.6 万字符、每轮重发，**单轮成本的一半以上在它身上**。只给总数的话，这个事实永远看不见。

**统一记账**：所有调模型的地方都走同一个 `recordUsage(来源, 输入, 输出)`——和黑塔币的 `applyLedger` 是同一个思想。要补的调用点：`useChatTurn`（主对话/复核/判心情/重说）、`broadcast/generate` 与 `reader`、`nms/deep-sleep-runner`、`nms/voice-runner`、`proactive`。

**已知缺口**：播报的搜索端点 `/v1/tools/search` **不回 usage 回执**，那部分统计不到。明细里要写明这一句，否则「今天用了 0.5M token」会骗人。

### 6.4 备份与迁移（补齐）

换机是刚需，但这套东西现在有三个缺口：**NMS dump 只在目标库为空时才恢复**（同机覆盖没做）、**备份不带「她能读的文件」**、**恢复完没有报告**。

- 恢复策略给两个选项：**同机覆盖** / **合并**
- **恢复之前强制先自动备一份**当前状态——这是唯一一次「误操作会把家弄丢」的地方
- 备份可勾选「带上她能读的文件」
- 恢复结束给一张报告：多少会话 / 记忆 / 表情 / 文件
- **备份包的字段名不许动**，老备份包要能继续读

### 6.5 版本更新提示

自建分发没有商店推更新，用户不会自己知道有新版本。

- 站点根目录放一个 `version.json`：`latest` / `min` / `url` / `note`
- App 启动（或进设置）时拉一次；**拉不到就静默**，不打扰、不卡启动
- 设置「关于」组显示当前版本；有新版挂红点，点开说清改了什么 + 下载按钮
- 当前版本低于 `min` 时按「必须更新」处理，文案更重
- ⚠️ **只 GET 一个静态 json，不上报任何设备或用户信息**——否则又多一笔隐私债

## 7. 黑塔币

一套界面，两个账本：不填昵称 = 单机（本地钱包），填了 = 共享市场。

新增：
- **连签加成**：连 7 天起签到奖励 ×1.05，断签归零；界面显示「还差 X 天」
- **成就 20 条**：签到、首次交易、首次爆仓、连签满月……
- **限价单**：双向，有效期 1h / 24h / 3d；**下单时顺手撮合**，不做定时扫盘，过期作废并明说
- **持仓分享卡**：纯图卡，可存相册、可发回对话（不带她的批注）
  - 样张：[盈利](prototypes-2026-11/coin-share-profit.png) · [空仓](prototypes-2026-11/coin-share-empty.png) · [破产](prototypes-2026-11/coin-share-bankrupt.png)；生成脚本 `tools/prototypes/gen-coin-share.py`
  - 尺寸 **1080×1440**，**浅色底**（用白天 A 那套 token：纸白 + 极淡青蓝光晕 + 左上半调点阵）；卡片是白玻璃 + 一层很淡的投影
  - 内容自上而下：`HERTA COIN` 与「虚构行情」标注 → **HTC / 信用点 + 价格 + 涨跌幅** → 一张描边卡（持仓 / 成本价 / 市值）→ **浮动盈亏（大号数字 + 百分比）** → 净资产与破产次数 → 域名水印
  - **不显示昵称**——分享图会流到群里，昵称属于账号信息，不该跟着跑
  - 红涨绿跌（与行情页一致）
  - **破产另有一套版式**（不跟正常卡共用）：**深墨底 + 底部一圈暗红光晕 + 一枚 -9° 的红色「破产」印章**
  - 破产卡内容：净资产（负数大字，红）→ 「已达负数 · 无下限」→ 负债合计 / 破产次数 / 重开起点 → 域名
  - 两套卡用底色做**状态区分**：浅色 = 正常或盈利，深墨 = 已破产。用户扫一眼就知道这张是哪种
  - **三种状态，两张底**：浅色底用于「盈利 / 亏损 / 空仓」，深墨底只用于「已破产」
  - **空仓卡**：持仓那一块换成**虚线占位框**，正中写「空仓 / 还没有持仓」；下面只留现金（数字后面紧跟「信用点」单位）与净资产、破产次数。吐槽用「空着。挺诚实。」
  - **每张都带一句她的吐槽**：**固定文案库，按状态挑一条，不调模型**（分享图不该等一次请求，也不该让模型在图上说错话）。用一句细的竖线引出，颜色比正文淡一档
  - 文案库（起手版，可改）：
    - 盈利：**运气不错。别当成能力。** / 这点钱也值得截图？ / 记住这个数，它会变成你下次的参照系。
    - 亏损：你的操作很有观赏性。 / 这就是你说的「低点买入」？ / 继续。我在看。
    - 空仓：空着。挺诚实。
    - 破产：**破产 {n} 次。你在这方面的确有天赋。** / 重开吧。这次别用同样的方式。 / 我记下了。下次换个姿势亏。
  - **字阶（小字为主，读数才放大）**：价格 84 / 盈亏大数 48 / 其余数字 32 / 标签 21–22 / 吐槽 24 / 域名水印 22。**除了两处大数，全卡都不超过 32**——分享图是被人瞄一眼的东西，字号越大越像广告
- **余额可负**：允许负数且**无下限**；负数时**不能开新仓，只能平仓**
- **做空 / 杠杆**：逐仓，开仓上限 = 净资产 × 3；借币按天计息（0.1%/天，惰性计算）
- **不做系统强平**：允许负数之后，强平、维持保证金率、定时结算器全都不需要了
- **破产 = 用户主动「重开」**：清空仓位、余额重置到 1000 HTC / 10,000 USDT、破产次数 +1（留疤，不是免费复活）
- **排行榜**：净资产榜（负数垫底并标红）+ 一个独立的**欠款榜**
- **单位改名**：界面上的一律改称**信用点**（不再出现 USDT）；交易对显示为「黑塔币 / 信用点」。**只改显示层**——代码字段仍叫 `usdt`，接口与存储不动，旧 APK 不受影响
- **收支统一走一个入口**：`applyLedger(昵称, 变动, 来源)`；签到、交易、成就、以后的小游戏都调它，来源打标（便于对账与封顶）

### 定价与口径（2026-11-05 二）

- **漂移改为随机正负**：`drift = ±0.0005`（按日期种子抽样，仍是确定性的）。**历史全量重算**——整条日线跟着变，测试向量与网页同源一起更新
- **限价单 = 条件单**：价格触及挂单价时，由系统按当时市价成交。挂单表共享可见，但**没有真实对手方**
- **净资产 = 现金 + 持仓市值 − 借入负债**（会计口径）。只有这个定义能让「负数」有意义；不算借入负债等于做空不欠账
- **单机与共享规则一致**：负余额、3x 开仓、限价单、成就全套都有，区别只在账本在本地还是服务端
- **重开之后**：连签归零；**成就保留**；破产次数本身算一条成就
- **频率限制保留**：买卖各 5 次/天、单笔 ≤1 万 HTC、5 秒冷却；限价单**成交时才计数**，杠杆开仓算一次买/卖
- **分享卡内容**：净资产 + 今日盈亏 + 持仓方向与倍数 + 破产次数（有的话）
- **欠款榜**：按负债绝对值从大到小；副指标显示「负债 / 净资产」比
- **老数据**：新字段全带默认（`short:null` / `orders:[]` / `achievements:[]` / `bankruptCount:0`），读时兜底、写时补全

### 从行情网页搬进来的东西（2026-11-05 四）

**背景**：行情网页退成**纯计算**（只留服务端算法），页面撤掉。网页上独有、App 里没有的东西要搬进来，否则页面一撤就丢。

| 搬 | 放在哪 |
|---|---|
| **币圈快讯** | 行情页 **K 线下方的折叠列表**；点一条定位到对应的那根分钟 K。每条带利好/利空方向与强度，和它冲击的那根 K 对得上 |
| **交易时段** | 行情页顶栏：工作日 09:30–11:30 / 13:00–15:00。现在 App 里完全没有，用户不知道什么时候能交易 |
| **免责声明** | 行情页底部：「行情、快讯与全部数据均为程序生成的虚构内容，仅用于娱乐与演示，不构成任何投资建议」 |
| **「永续」标签** | HTC/USDT 标成永续——有做空和杠杆之后这么叫才说得通 |

**不搬**：生成原理说明段、本场密钥、保存行情图。最后一项由**持仓分享卡**覆盖，做两份等于两份维护。

**数据从哪来**：快讯由**服务端随行情一起下发**（复用 `fc/coin-api/news-pool.js` 那套种子抽取），不在客户端重算——否则两端逻辑一漂移，快讯就和 K 线对不上了。整个列表约 2 KB，不值得为它单独开接口。

**边界（重要）**：快讯只出现在行情页并标着「虚构」；播报只用真新闻；**她不在播报里引用快讯**。播报自己的底线是「不编新闻，宁可少发」——混进虚构快讯，这条底线就没了。

### 结算与每日事务（2026-11-05 三）

**借币利息**
- 利率 **0.1%/天**，按**开仓时锁定的价值**算（不随行情浮动）
- **不满一天不计息，但零头保留**——今天 15:00 开仓，明天 15:00 才算满 1 天
- 扣的是**信用点**，可以扣成负数（余额本来就可负）
- 账户上存 `borrowedAt` / `lastInterestAt`

**每天第一次打开市场时，结算一次**
- 结两件事：**借币利息** + **清理过期挂单**
- **不做结算单**，静默执行（用户不会收到「本日结算」的提示）
- 用 `lastSettleDay`（按 serverTime 的日期）判断是不是当天第一次
- **隔了几天才打开：一次补结全部欠的天数**——不上线躲不掉利息

**其余访问仍走惰性补记**：任何时候读账户或交易，都按「距上次计息过了几个整天」补齐，保证数字永远是对的。日结只是「强制跑一次 + 顺带清挂单」。

### 经济系统（后续，不在本轮）

- **小游戏 = 新的「赚」的出口**：有赚有亏
- **逻辑跑在客户端**（本地），服务端只做两件事：**记一笔账**、**卡每日上限**
- 输不设上限（余额本来就可负），但**单次大额下注要二次确认**
- **超出上限：截断**——只发剩余额度（还剩 30、这局赢 50，就发 30），不拒绝、不挂账
- **每日计数**：`dailyGameIncome = { date, sum }`，按 `serverTime` 的日期重置
- **收入统一走记账入口**：`applyLedger(昵称, 变动, 来源=game)`

**经济参数放哪**：`state/economy.json`（OSS 上一个独立小文件）

```json
{ "dailyGameCap": 500, "maxBet": 200, "expectedPayout": 0.9 }
```

- **手改这个文件立刻生效**：不用发版、不用重新部署、不用后台
- **只读一次、不需要锁**（极少写），比 `state/coin.json` 便宜
- **读不到或格式错就用代码里的默认值**，绝不让市场因此挂掉

**残留风险（明确接受）**：客户端算结果 = 改包就能伪造。但被每日上限关住，最坏是「一天多拿一份上限」，不是把整个经济刷穿。这是拿「有限的可伪造」换「不用写两份逻辑」。

> **为什么允许负数反而更简单**：它把杠杆从「保证金模型」降成「记账模型」——抵押率、维持保证金率、强平、定时结算器、穿仓兜底全部省掉，**新增基础设施为零**。
>
> 剩下的只有两道护栏，缺一不可：**开仓时按净资产卡 3 倍**（否则 1000 块开 10 亿的空单，一笔就能把余额打到 -10 亿）、**负数时禁止开新仓**（否则可以靠不停加仓绕过一切）。

> **成本（2026-11-04 查证）**：阿里云 FC 3.0 按量付费，CU 单价 0.00011 元、调用 75 CU/万次、vCPU 1.0 CU/(vCPU·秒)、内存 0.15 CU/(GB·秒) → **单次调用约 0.000002 元（十万次约两毛钱）**。
>
> 但**成本主控旋钮不是这些功能，是行情页的轮询频率 × 响应体大小**：按每人每天开 20 次、每次 5 分钟、10 秒轮询、响应 30KB 估算，5 人 ≈ ¥2/月、50 人 ≈ ¥16/月、500 人 ≈ ¥160/月，其中**流量占八成**。把响应压到 8KB、轮询改 30 秒、页面不可见时不轮询，500 人可降到 ≈ ¥40/月。

## 15. 主题与扩展（2026-11-04 追加）

> 为什么停在 CSS 层、槽位只收随包代码：见 [ADR-0004](adr/0004-theme-extension-stops-at-css.md)。

### 15.1 分层的扩展点

| 层 | 能力 | 谁能填 | 承诺 |
|---|---|---|---|
| **L0 token** | 全局颜色 token × 日/夜两套 | 主题包 | 稳定、可校验、可回滚 |
| **L1 CSS 全接管** | 主题自带 CSS，按 `data-part` 锚点覆盖任意样式（含 grid/order 重排） | 主题包 | 锚点稳定；**类名不算接口** |
| **L2 组件槽位** | 整块替换：消息气泡与消息项 / 左轨+顶栏 / 输入条 / 开屏 | **只有随包代码** | 架构预留，逐版可扩 |
| **L3 第三方代码** | — | **永不开放** | 代码里留一个空注册表 |

理由：在「陌生人在 GitHub 上发主题」的前提下，L3 等于把所有用户交给第一个发恶意主题的人。L1 已经足以做出跟现在完全不像的界面——能重排、能改形状、能改留白，只是不能往 DOM 里加节点。

### 15.2 契约

- **主题包**：zip（`theme.css` 必需，可带资源），由 `skin.json` 声明身份（`id` 非空）——沿用桌面端约定
- **不枚举 token 契约**：token 只是 CSS 的一个子集，主题写 `--ink: #xxx` 与写 `.bubble{…}` 是同一件事；契约只剩**锚点 + 版本 + 优先级**三条
- **缺字段继承默认**；**`minAppVersion` 不满足则拒绝安装**
- **同时只有一个主题生效**，选择跨重启保留
- **用户显式设置永远优先**：`当前的脸` / 聊天背景 / 日间夜间 / 字体，主题盖不掉

### 15.3 锚点

- 在关键节点上加 `data-part="…"`；**只承诺属性名不变**，class 名随时可重构
- 铺在骨架那一批（B2），因为那批本来就要逐个碰页面结构

### 15.4 前置架构债

`styles/settings-suite.css` 有 **28 个 `--ss-*` 局部 token**，管着设置 / 她能做什么 / 备份迁移 / 工具调用记录四页。

主题既然能直接覆盖这四页的样式，本条**已从「契约前置债」降级为「内部整洁」**：不做也不会缺功能，做了能让以后的样式重构少踩坑。

### 15.5 分发

- **一期**：链接导入 zip —— `HertaHttpPlugin` 拉取 → `fflate` 解压（已是依赖）→ IndexedDB 存 → 运行时注入。**零原生改动**（手机端没有 Filesystem 插件，`assets/public` 随 APK 只读）
- **二期**：GitHub 仓库里的 `themes.json` 索引，App 拉索引浏览安装

## 16. 关于 · 赞助 · 开发人员（2026-11-04 追加）

### 16.1 三页是什么

| 页 | 是什么 | 不是什么 |
|---|---|---|
| **关于** | 入口页：版本号、开发人员、赞助名单、反馈渠道 | 不是一个设置页 |
| **赞助** | 一张**上月的赞助名单** + 一个「我要赞助」按钮 → **弹层**里放微信 / 支付宝收款码 + QQ 群号（带复制） | 不是一个收款页：不把码平铺出来，也不在别处要钱 |
| **开发人员** | 作者本人（谁写了代码） | 不是贡献排行榜 |

> **插件站有独立的一份**：手机端的「开发人员」只写 App 作者与灵感来源；DSH 插件的开发人员与授权在插件站自己的页面（线上站点的 `/dsh/devs.html`），因为它要写的是**四层来源与两套条款**（代码 MIT、语音与人设语料不在 MIT 内），和 App 那份不是一回事。
| **灵感与帮助** | 取材自哪些作品（`work`）+ 谁给过点子（`idea`） | 不是开发名单，两类不混排 |

入口：手机端在**设置最底部新开一组「关于」**（赞助 · 开发人员 · 版本号），点进去各自是整屏页。网站上也放同两份内容。

### 16.2 名单从哪来

一份**远程 JSON**，网站与 App 都读它；改名单不用发版：

```json
{
  "devs": [{ "name": "…", "role": "作者", "link": "https://github.com/…" }],
  "inspirations": [
    { "name": "…", "kind": "work", "what": "人格 / 叙述 / 开屏", "link": "…" },
    { "name": "…", "kind": "idea", "what": "想到了共享市场与连签", "link": null }
  ],
  "supporters": [{ "month": "2026-10", "names": ["…", "…"] }],
  "sponsor": {
    "wechatQr": "https://…/qr-wechat.png",
    "alipayQr": "https://…/qr-alipay.png",
    "qqGroup": "123456789"
  }
}
```

- **开发人员**：只写作者本人 + 每人负责哪一块，不写提交数
- **灵感与帮助**：页面上分两小段——「取材自」放 `kind: work`（被取材的作品与作者），「点子来自」放 `kind: idea`（给过点子的人）。两段措辞不同：作品是「取材」、人是「谢谢 TA 想到了这个」。**都不混进开发名单**
- **赞助名单**：按月分组，页面上默认展开**最近一个月**，历史折叠
- 读不到 JSON 时：显示「名单暂时取不到」，不空着、不塞假数据

### 16.3 反馈与已知问题（2026-11-05 五）

- **反馈三件套**（全部飞书，链接只写线上站点的 `config.js` 两行）：
  - **提交**：多维表格表单（`feedback`）——能收截图、不要求账号
  - **自查**：已知问题页 `issues.html`——把还没修的边界先列出来，挡掉重复反馈
  - **回头查**：飞书查询视图（`feedbackQuery`）——用户自己看提交过的那条现在什么状态
- 选飞书而不是收集表，是为了每条反馈都进一张能改状态的表（待处理 / 已修 / 不修），而「状态」这一列只在表里、不在表单里
- ⚠️ **查询页靠「联系方式」定位**：这一项若留空，用户就查不到自己那条。要么改成必填，要么在表单说明里写清「想查进度就填联系方式」
- **链接只写一处**：线上站点 `config.js` 里的 `feedback`；留空时「反馈」自动指向「已知问题」页，不出死链
- **入口三处指向同一个表单**：网站顶栏、网站页脚、App「设置 → 关于」
- **已知问题页**：网站 `issues.html` + App 里同样一份。列的是**还没修**的边界（扫描件 PDF 无 OCR、老格式读不了、旧 WebView 抽不出字、低端机帧率、深睡依赖 WebView、备份不带能读的文件、表情只存引用、没有 iOS、没 Key 只能看）
- **反馈要素**：手机型号 / Android 版本 / App 版本号 / 复现步骤——页面上直接写出来提醒
